# HR schema

H1 applies `schema.sql` in the `hr` database on every deploy. It applies `seed.sql` only when `use_cases.hr-data.seed` is `true`. The same cluster has an empty database named `agent_state`. No HR table is created there. The god agent adds its checkpoint tables later.

v1 stores one row per person. A transfer updates `manager_id` on that row. A later history table would be a new table, not extra columns on this primary key.

## employees

| Column | Type | Rule |
|---|---|---|
| `employee_id` | text, primary key | Stable business id. Not the Cognito `sub`. |
| `cognito_sub` | text, unique, nullable | Filled when the person has signed in once. Lookup key for H3. Several nulls are allowed. |
| `email` | text, unique, not null | Stored for operators. No tool returns it. |
| `full_name` | text, not null | In the demo seed this equals `employee_id`. See the guardrail note in [Tools](tools.md). |
| `manager_id` | text, nullable, references `employees` | Null only for the top of the seed. One hop. `ON DELETE RESTRICT`. |
| `legal_entity` | text, not null | v1 has one value, `demo`. |
| `status` | text, not null | `active` or `terminated`. |
| `hire_date` | date, not null | |
| `probation_end_date` | date, not null | On probation while this date is after the tool's UTC date. The end date itself is not probation. |

## salaries

| Column | Type | Rule |
|---|---|---|
| `employee_id` | text, primary key, references `employees` | One current row. |
| `base_salary` | numeric(12,2), not null, zero or more | Never selected before OPA allows. |
| `currency` | text, not null | |

## leave_balances

Primary key `(employee_id, leave_type)`. `leave_type` is `annual` or `sick`. `remaining_days` is numeric(6,1), not null, zero or more.

A pending request does not change `remaining_days`.

## leave_requests

| Column | Type | Rule |
|---|---|---|
| `request_id` | text, primary key | Generated by the tool. |
| `employee_id` | text, not null, references `employees` | Always the caller. |
| `leave_type` | text, not null | `annual` or `sick`. |
| `start_date`, `end_date` | date, not null | `end_date >= start_date`. |
| `reason` | text, not null | Not written to logs. |
| `status` | text, not null | `pending`, `approved`, or `rejected`. The tool inserts `pending` only. |
| `idempotency_key` | text, not null | Unique with `employee_id`. |
| `decided_by` | text, nullable, references `employees` | Set by `record_leave_decision` from the reviewer's token. Null while pending. |
| `decided_at` | timestamptz, nullable | Set in the same update as `decided_by`. |

## payroll_items

Primary key `(employee_id, item_type, period)`. `item_type` for v1 is `telephone`. `period` is `YYYY-MM`. `amount` is numeric(12,2), zero or more. `currency` is text.

Index `employees(manager_id)` for the direct-report query.

## decision_log

Append-only. No amounts, no leave reason, no names.

| Column | Type |
|---|---|
| `id` | bigserial, primary key |
| `at` | timestamptz, not null, default now |
| `action` | text, not null |
| `caller_employee_id` | text, not null |
| `target_employee_id` | text, nullable |
| `allow` | boolean, not null |
| `reason_code` | text, not null |
| `agent_id` | text, not null |
| `session_id` | text, nullable |
| `trace_id` | text, nullable |
| `decided_by_layer` | text, not null, `opa` or `tool` |
| `policy_version` | text, not null |

`tool` means the Lambda decided before OPA, for example `SERVICE_DISABLED` or `NOT_MAPPED`. A Cedar deny never reaches the Lambda, so Cedar decisions are in Cedar's own decision log, not in this table. H4 confirms which log group that is before the SIEM filter is written. The SIEM joins the two on `session_id` and `trace_id`.

The `hr_audit` role may only INSERT into this table. No role in the HR modules may UPDATE or DELETE it.

## Demo seed

Loaded only when `seed: true`. The script upserts only the nine ids below. If any other `employee_id` is already present, it exits with an error and writes nothing. The clock in tests is frozen at `2026-11-13`, so "last month" is `2026-10`.

`full_name` equals `employee_id`. The gateway guardrail anonymizes personal names on the way back to the model, so the demo does not store personal names.

Leave, all in days: E1 annual 14, sick 10. P1 annual 14, sick 10. Others annual 14, sick 10.

Telephone allowance: one row, E1, period `2026-10`, amount `25.00`, currency `USD`. No other person has an allowance row. A denied caller must not learn that.

Hire date for everyone except P1 is `2020-01-01`. P1's hire date is `2026-09-01`. `legal_entity` is `demo`. Emails are `{id}@example.com`. `cognito_sub` stays null until a real sign-in is mapped in a test.
